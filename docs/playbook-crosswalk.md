# Playbook crosswalk

Maps the firm's Harvey Prompt Playbook (Corporate & M&A), section 3.4 Due Diligence Review,
against the 591-column corpus — in both directions.

## The playbook lives in its own repository

It carries the practice's own methodology — prompt text and the field lists behind it — which
is a different class of material from the engine that runs it. The kernel reads it by path and
runs perfectly well without it; the crosswalk is analysis, not runtime.

```bash
export DILIGENCE_KERNEL_PLAYBOOK=/absolute/path/to/diligence-playbook
```

Unset, the kernel looks for a `diligence-playbook` checkout beside this one. Absent entirely,
the crosswalk scripts say so and the crosswalk test skips.

## Provenance, which changes what this proves

The playbook was **substantially model-generated by a senior partner**, not written from
observed practice. Agreement with the corpus is evidence that two syntheses agree, not that
either is right. Neither side is validated against how the practice actually works.

## The four moves are answered by different layers

Section 3.4 provides, per workstream, prompts for (i) summarizing a document, (ii) identifying
risks, (iii) flagging missing items, (iv) synthesizing findings. Scoring all four against
extraction columns reports design as deficiency:

| Move | Answered by |
|---|---|
| (i) summarize | Harvey extraction columns |
| (ii) identify risks | Extraction for the facts; **human columns** for rating and consequence — `00a` section 10 reserves those |
| (iii) flag missing | `Referenced but Not Produced`, the coverage register, the test sets |
| (iv) synthesize | Derived artifacts and the memo — filters over cells, never fresh questions |

## Matching is by embedding, and the threshold is calibrated

Term overlap was tried and discarded: it resolved 42% of fields while 95% of their distinct
terms appeared somewhere in the corpus, and called covered concepts gaps — `drag-along`,
`anti-dilution`, `liquidation preference` all have columns of their own.

`text-embedding-3-small`, cached by content hash. `--calibrate` scores ten pairs confirmed by
reading the corpus: **10/10 in the top five, 6/10 first**, lowest score on an expected column
0.48. `COVERED_AT` is 0.45, below that minimum, so a covered concept is not called a gap.

## Findings

**82% of extraction fields are answered** (55 of 67).

Four genuine gaps, of twelve uncovered fields — the other eight belong to 3.4.16 and are
answered by derived artifacts rather than columns:

| Gap | Note |
|---|---|
| Benefit plan compliance (401(k), ACA, pensions) | Uncovered by both documents; `00a` section 2 lists it as an open scope question |
| WARN Act obligations | No column anywhere |
| Property type (office, warehouse, retail) | Tables 13 and 14 record interest and address, not use type |
| Unregistered trademarks and domains | Borderline at 0.437 |

**212 columns answer nothing the playbook asks**, and the split is the finding:

- **124 in workstreams the playbook has no prompt for** — intake, debt and liens, insurance,
  environmental. The playbook is incomplete, not the corpus wasteful.
- **88 in workstreams a prompt does cover.** Worth reviewing, though many are deliberate:
  `Documents in Unit` feeds other columns rather than a reader, and `Entity File Number`,
  `Early Exercise and 83(b) Election` and `Immigration Dependency` are the corpus being more
  thorough than the playbook.

## Running it

```bash
python scripts/extract_playbook.py --pdf <the pdf> --out $DILIGENCE_KERNEL_PLAYBOOK/corporate-ma-3.4.json
python scripts/crosswalk.py --calibrate
python scripts/crosswalk.py --out $DILIGENCE_KERNEL_PLAYBOOK/crosswalk.json
```
